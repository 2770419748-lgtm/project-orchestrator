# 软件项目总控 Agent｜V3.1 最小上下文版

保留 1 Core + 1 项目状态模板 + 5 Skills 架构。这是供 Agent 读取的工作规范，不含自动调度、权限执行或上下文压缩程序。

## 结构与使用

- AGENTS.md：共同授权、路由、委派、失败处理与完成标准。
- PROJECT_STATE.md：带核验来源和验证证据的当前状态模板。
- .agents/skills/：development、testing、migration、release、maintenance，按任务加载。

把目录内容合并到目标项目根目录，保留 .agents 隐藏目录。已有 AGENTS.md、PROJECT_STATE.md 或同名 Skill 时先检查冲突并合并，不直接覆盖用户内容。实际加载和发现方式取决于宿主平台；未自动发现时按 AGENTS.md 的路径读取相关 Skill。

首次启用先只读了解项目。用户要求实施、修复或初始化状态后，在授权范围完成工作和必要状态写入。没有正式需求系统时，使用用户请求摘要与验收条件即可。

## 平台与模型

原版的 GPT-5.6 Sol + high 保留为可选执行配置建议；需要它时通过宿主界面或实际支持的 Agent 配置设置。Markdown 和 Skill 本身不切换模型。无法指定或核验时如实说明，按宿主当前配置执行；用户明确要求必须使用指定配置时，不把未核验的配置当作满足要求。

子 Agent 需要宿主提供真实委派工具。无该能力时由总控串行处理。Skill 加载不产生独立 Agent，也不自动卸载上下文；本方案通过按需读取、简短交接和状态快照减少后续重复信息，实际上下文或用量变化需测量。

## V3.1 调整

- 精简 Core，专项步骤放回对应 Skill。
- 小任务直接执行必要验证；完整交接仅用于委派或复杂交接。
- 用新增证据和阻塞条件管理返工，替代固定两轮后停工。
- 状态记录补充核验时间、来源、代码标识和授权核对线索。
- 区分 Skill 与 Agent，去除 Markdown 能强制模型或自动压缩的暗示。
- 测试失败回到实际负责角色，明确测试源码的修改边界。
- 补全初始化、无 Git、并行集成与任务状态语义。

本包是模板，未安装到实际项目；适配项目后仍需结合真实任务观察其行为。
