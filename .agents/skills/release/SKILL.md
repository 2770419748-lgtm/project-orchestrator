# 发布与回滚

按项目 AGENTS.md 的规模与风险分流确定执行者并核对授权；生产写入按高风险处理，由总控协调、委派执行并安排独立复核。发布前检查可先在已授权范围完成；尚未获得相应部署授权时，准备具体版本、目标环境、影响和恢复方案，等待必要授权。已有发布授权覆盖当前版本选择条件、环境和动作时继续，无需重复询问。

## 发布前

确认代码及构建产物标识、未提交修改、测试证据、配置、迁移要求、恢复或补救方案，以及发布后需要验证的业务路径。构建和发布对应同一明确版本；需要专门验证流程时读取 [testing](../testing/SKILL.md)。

- 未解决 P0（不可用、数据损坏或严重安全问题）：禁止常规发布。事故修复发布必须有明确修复目标、相应授权、风险和验证方案。
- 重要 P1（核心流程失败或重要功能异常）：解决后发布，或取得用户对具体风险的明确接受。

## 执行与验收

锁定版本与环境，构建或复用已核验产物，执行部署，核对运行版本，完成 Smoke、关键业务路径和错误检查。发布命令成功不足以证明可用。记录环境、版本或构建 ID、时间、验证证据和残余风险。

部署失败时先确认实际状态。外部写入结果不明确时，核对服务或部署记录后再决定是否重试，避免重复操作。代码问题交回对应实现角色；部署配置问题在当前授权内修复。

回滚仅在当前授权或预先批准的方案覆盖触发条件、环境与动作时执行；数据库与应用回滚需核对兼容性。否则先报告影响和具体恢复方案，完成其他已授权的缓解工作。

发布后正在验证或修复时保持 IN_PROGRESS；关键步骤被具体外部条件阻塞时标记 BLOCKED，并说明解除条件；等待用户要求的验收或决策时标记 REVIEW，并明确待审事项。发布后关键验证未完成时不能将任务报告为 DONE；汇报时明确实际运行状态。
