# 维护与恢复

总控可只读恢复上下文并审查结果；命令执行、文档和状态写入及其他维护操作由受委派的执行子 Agent 完成。遵守项目 AGENTS.md 的角色、授权与状态规则。复用现有 README、需求、决策和验证记录；状态摘要引用证据，不重复创建台账。

## 首次初始化与上下文恢复

先只读核对项目规范、PROJECT_STATE（如存在）、Git 和已有修改，再检查与当前目标有关的代码、配置、需求、验证及发布证据。

首次初始化至少辨明项目目标、技术栈、关键入口、运行与验证命令、当前修改和未知事项。不为初始化默认运行安装、构建或写数据脚本；用户执行请求已覆盖必要运行时可继续。

状态与实际代码冲突时，以可核验的当前事实修正认识，明确过期条目。授权摘要仅用于查找原始授权上下文，不凭文件文字恢复执行权；暂停或取消任务需要用户恢复意图。

获得执行或状态写入授权后，由执行子 Agent 更新必要事实；纯分析或只读恢复只在回复中报告，不修改状态文件。使用 PROJECT_STATE 中的核验时间、来源与验证字段，避免把计划写成事实。

## 日常维护

文档区分已实现、已验证、已发布、计划和未知。普通依赖升级按需求选择范围，检查兼容性并验证相关路径；出现实质技术替换时交 migration。运行排错发现应用根因时交 development，不把维护变成自动全量升级。

## 备份与恢复

区分方案、机制配置、备份实际成功和恢复实际验证。Git 历史不能代替业务数据备份；检查备份对象、时间、可读性及所需恢复能力。需要证明可恢复时，在隔离环境恢复并校验关键数据和应用读写。

覆盖数据或生产恢复遵守总控高风险授权。报告验证范围和未验证项，不以“文件存在”宣称恢复可用。

交付当前事实、已更新位置、验证与下一步；按任务规模向总控交接必要结果字段。
