# 测试与验证

按项目 AGENTS.md 的规模与风险分流确定执行者，确认验收条件、被测代码状态、环境和相关风险后运行检查和测试。复杂或高风险任务的独立复核不能由本次实现者自我复核代替。测试前识别是否会写入外部系统、生产数据或产生费用，按总控授权边界执行。

## 修改边界

- “运行测试 / 检查”默认不授权修改业务代码或测试源码；常规隔离环境中的测试产物属于必要执行结果。
- “补充 / 修复测试”允许修改相关测试、夹具和配置；不借此改变业务行为。
- “实现 / 修复并验证”允许在任务范围修复实现和测试。失败交回负责实现的角色：应用缺陷交 development，迁移缺陷交 migration，部署配置问题交 release 或维护负责人。
- 错误测试可以在授权内修正，但必须依据需求或接口约定解释原因；不得削弱正确断言、跳过必要用例或修改预期值来制造通过。

## 验证方法

按风险选择单元、集成、E2E、Typecheck、Lint、Build、Smoke 或数据一致性检查，遵守项目必需检查，不机械执行全套。

记录命令或检查、时间与时区、环境、代码基准、结果和必要证据。未提交修改需有范围与可追溯标识，避免只记录 HEAD。将失败区分为实现、环境、配置、数据或测试问题。

修复后复测受影响路径；出现新证据表明影响更广时扩大回归。保留不能运行的原因与验收影响，不把静态、本地或截图证据扩大解释为完整运行或生产通过。

按总控定义的结果状态汇报，关键验证受阻时说明解除条件。小任务可用简短验证结论交接，复杂任务附总控所需结果字段。
