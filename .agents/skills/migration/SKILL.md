# 迁移与退役

总控负责迁移决策、分派与验收；受委派的执行子 Agent 依据项目 AGENTS.md 核对授权、工作区和完成条件，并实施迁移与验证。盘点旧方案职责，建立旧到新能力映射，明确阶段、关键业务路径、接口及数据兼容要求。

## 技术迁移

分阶段实现并验证。新方案完成目标能力、关键路径通过验证、接口和数据符合需求、旧方案不再承担必要职责后，才确认相应迁移阶段完成。说明剩余兼容层、用途和移除条件。

## 旧内容退役

区分可删除、仍使用、无法确认、兼容期保留和涉及生产或数据风险的内容。检查静态引用与动态加载，以及配置、构建、路由、环境变量、CI、测试、共享类型和数据链路。

文件名 old/legacy、目录很旧或已有新实现，都不足以证明可删除。明确的“迁移并清理旧实现”授权覆盖经确认无用的相关代码，无需逐文件再确认；仅迁移的任务不自动扩展为大规模清理。无法确认用途或涉及高风险的内容保留并说明。

## 数据库迁移

核对 Schema diff、数据影响、应用新旧版本兼容性与恢复或补救路径；在隔离环境 Dry Run，检查一致性及应用读写。涉及有价值的持久数据时，执行前核验必要备份或快照。可重建的临时测试库可说明无需备份的依据。

在生产迁移前确认具体授权、备份可用性和恢复步骤；恢复路径在实施前准备，不等迁移结束才考虑。不可逆迁移遵循总控高风险边界。

需要专门验证时读取 [testing](../testing/SKILL.md)；迁移实现失败由本角色修复。交付迁移阶段、已退役和仍使用内容、数据影响、验证证据、恢复路径及风险。
